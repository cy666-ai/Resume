目标：修改 skills「筛选简历」，让“极大输出的报告”的第二部分“详细分析”不再进行测试/匹配性逐项展开，而改为更轻量的候选人简述。

现状梳理：
1. skill 文档在 [.claude/skills/筛选简历/SKILL.md](.claude/skills/筛选简历/SKILL.md) 中定义了第二部分“详细分析（按岗位分组）”，当前描述包含：
   - 基本信息
   - 技能匹配度（匹配技能、缺失技能、额外技能）
   - 经验匹配度分析
   - 教育背景匹配度
   - 综合评分和建议
2. 实际输出逻辑在 [.claude/skills/筛选简历/scripts/generate_report.js](.claude/skills/筛选简历/scripts/generate_report.js) 的 `generateGroupedReport()` 中实现：
   - 第一部分：候选人总览
   - 第二部分：详细分析（当前会输出技能/经验/教育/人才库/详细分析全文）
   - 第三部分：岗位要求对照
   - 第四部分：总结与建议
3. 第二部分目前并不会“运行单元测试”之类的测试行为；这里更像是“做详细匹配分析/逐项展开”。如果你的意思是“第二部分不要再做详细匹配展开”，那么主要改动点就是第二部分的输出结构和 skill 文档说明。

建议实现：
1. 只改“报告第二部分”的呈现，不动筛选评分、归档、人才库查重逻辑。
   - 保持 `analyzeResumeFromPdf()`、评分、归档规则不变，避免影响当前筛选结果。
2. 将第二部分从“详细分析”改为“候选人简述”或保留标题但内容简化。
   - 每位候选人只输出：姓名、岗位、地点、工作年限、综合评分、推荐等级、一段简短总结。
   - 不再输出：
     - 技能匹配度分项明细
     - 匹配技能 / 缺失技能 / 额外技能列表
     - 经验匹配度分项说明
     - 教育匹配度分项说明
     - 第一学历校验细节
     - 长篇 `analysis` 说明
3. 为避免歧义，我建议第二部分标题同步改成“第二部分：候选人简述（按岗位分组）”。
   - 这样文档和输出一致，用户更容易理解这部分不再是深度分析。
4. 同步修改 skill 文档 [.claude/skills/筛选简历/SKILL.md](.claude/skills/筛选简历/SKILL.md)：
   - 把第二部分描述从“详细分析”改成“候选人简述”
   - 明确说明该部分不再展开测试/匹配明细，仅保留简述摘要
5. 不改第三部分“岗位要求对照”。
   - 因为它本身就是独立对照表，若一并删除会改变报告用途太大；当前需求只指向第二部分。

具体拟改文件：
1. [.claude/skills/筛选简历/scripts/generate_report.js](.claude/skills/筛选简历/scripts/generate_report.js)
   - 修改 `generateGroupedReport()` 中第二部分的标题和输出字段
2. [.claude/skills/筛选简历/SKILL.md](.claude/skills/筛选简历/SKILL.md)
   - 更新第二部分说明文字，和实际行为保持一致

预期效果：
1. 报告整体结构仍保留四部分。
2. 第二部分输出显著变短，更适合“大输出报告”场景。
3. 不影响评分、名单记录、归档目录、人才库查重。

风险与注意：
1. 如果你说的“不要进行测试”其实是指“整个 skill 不要再做任何匹配评分/分析”，那将是另一类改动，需要进一步缩减第一部分、第三部分甚至归档依据。
2. 当前我按“仅简化第二部分，不改变筛选逻辑”来设计，这是最小且安全的改法。
